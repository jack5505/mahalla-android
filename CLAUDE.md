# Claude Code

Правила выше действуют всегда. Ниже — то, что специфично для Claude Code
и для работы в GitHub Actions.

## Где ты работаешь

Основная разработка идёт **в GitHub Actions** через
`anthropics/claude-code-action@v1`:

- `claude.yml` — реакция на `@claude` в комментарии issue/PR, в ревью или в
  теле нового issue. Задача — из контекста. Ветки `claude/*`.
- `claude-dev.yml` — ручной запуск (Actions → Run workflow), задача в prompt.
  Дополнительно поднят docker-бэкенд + postgres/redis на localhost:8080
  (если задан `BACKEND_IMAGE`; health — `BACKEND_HEALTH_PATH`).

Иногда та же работа идёт локально в терминале — правила те же, различается
только окружение (см. AGENTS.md) и то, что git локально требует явной команды.

## Что это значит на практике

- **Каждый прогон начинается с нуля.** Между задачами ничего не переносится:
  ни память, ни история сессии. Всё, что должно пережить задачу, — в
  репозиторий: код, `docs/`, `CHANGELOG.md`, issue.
- **Внутри прогона тебя никто не поправит.** Поэтому проверка — машинная:
  `./gradlew testDebugUnitTest` и `assembleDebug` до пуша, всегда.
- **Отчёт — единственное, что увидит человек.** Пиши в него то, что не видно
  из диффа: что проверено и с каким результатом, где пришлось гадать, что
  осталось.

## Инструменты

Разрешены Bash, Read/Write/Edit, Glob/Grep, WebFetch, WebSearch, Task/Agent,
TodoWrite — список в `claude_args: --allowed-tools` обоих workflow.
`gh` работает: `GH_TOKEN` проброшен, права по `permissions` job'а — issue и PR
создавать и комментировать можно.

Инструмент нужен, а он запрещён — **не обходи**, напиши в отчёт: список
правится в workflow, это дешевле, чем костыль в коде.

## Перед тем как открыть PR

Прогони ревью диффа субагентом в свежем контексте (`Task`) — он не видел, как
ты писал код, и ловит то, что замылилось. Ревью PR в этом проекте уже трижды
находило некомпилируемые файлы, доехавшие до `main`.
