# 0006. Источник истины у PIN — сервер; app-lock проверяет код локально

**Статус:** Принято (issue #102)

## Контекст

До issue #102 PIN был двух видов и они друг о друге не знали. Локальный
(PBKDF2 + Keystore, [ADR 0004](0004-pin-pbkdf2-keystore.md)) отпирал экран
входа, а `pin-code-controller` бэкенда приложение не вызывало вовсе — 0 из 7
ручек. При этом токены выдаёт как раз серверный PIN-шаг (`auth/setup-pin` /
`auth/pin-login`, issue #51). Два разных кода на один вход человек не
различает, и расхождение было записано как незакрытое ещё с issue #42.

Замок приложения (PIN при возврате из фона) требует ответить, кто из двух
хранилищ главный.

## Решение

**Сервер — источник истины. Локальный Keystore-хэш это офлайновая копия того
же кода.** Инвариант держит `SecurityRepository`: локальный хэш пишется
**только** PIN'ом, который бэкенд уже принял — `auth/setup-pin`,
`auth/pin-login`, `pin/change`, `auth/pin-resume`. Двух разных PIN больше нет.

App-lock при этом проверяет код **локально**, а `auth/pin-resume` вызывается
после успешной проверки и его отказ разблокировку не отменяет: он продлевает
серверную сессию, а не решает, пускать ли человека в его же приложение.

## Последствия

- Экран блокировки работает без сети. «Только сервер» превратил бы приложение
  в кирпич в метро — это и есть главный риск задачи, названный в issue.
- **PIN стал шестизначным** против четырёх в ТЗ: бэкенд принимает ровно
  `^[0-9]{6}$`. Менять — на стороне `jack5505/mahalla`.
- Отказ Keystore при смене PIN разрешается в пользу сервера: он новый код уже
  принял, поэтому локальная копия **стирается**, а не остаётся прежней (иначе
  замок открывался бы кодом, которого бэкенд не знает). Замок тогда просто не
  вооружается и включится при следующем входе — экран безопасности говорит об
  этом плашкой.
- Счётчик попыток: в серверном режиме (`pin-login`, `pin/change`,
  `pin/biometric`) считает бэкенд, свой не заводим. На экране блокировки он
  локальный — код там проверяется без сети, и считать серверу нечем; исход не
  «заблокировано навсегда», а выход в SMS-вход.
- Замок вооружается только когда есть сессия **и** локальная копия PIN: замок,
  который открыть нечем, и есть запирание пользователя вне приложения.
- Отсрочка 30 секунд обязательна: код из SMS копируют в приложении сообщений,
  Telegram-вход уходит в Telegram (issue #46), пополнение — в браузер
  провайдера (issue #93).
- Подписка на `ProcessLifecycleOwner`, а не на колбэки Activity: он один
  отличает уход в фон от пересоздания Activity, а его приложение делает на
  смене языка и темы.
- Замок — оверлей поверх навигации, а не маршрут: накрывать он обязан и
  онбординг, и экран обновления (issue #80), и ввод адреса бэкенда
  (issue #26), не трогая back stack и deep links.
