# 0007. Источник истины у PIN — сервер, локальный хэш — его офлайновая копия

**Статус:** Принято (issue #102)

## Контекст

PIN был двух видов, и это записано как расхождение ещё с issue #42 и #51:
локальный четырёх-шестизначный код в Keystore (ADR 0004) и серверный
шестизначный у `pin-code-controller` — семь ручек, из которых приложение не
звало ни одной. Не звало и `auth/session/check` с `auth/pin-resume`.

Два разных PIN на один вход человек не различит: сменил код в профиле — экран
блокировки продолжает принимать прежний; вошёл новым — замок не открывается.
Пока замка не было, расхождение ничего не стоило; с app-lock его надо закрыть.

Цена ошибки несимметрична и названа в самом issue: **ошибка здесь запирает
пользователя вне приложения**. Экран блокировки, которому нужна сеть, — это
кирпич в метро, в самолёте и в роуминге.

## Решение

**Сервер — источник истины. Локальный Keystore-хэш — офлайновая копия того же
кода**, и держится инвариант: локальная копия перезаписывается **только**
кодом, который бэкенд уже принял (`auth/setup-pin`, `auth/pin-login`,
`PUT pin/change`, `auth/pin-resume`).

Следствия этого выбора:

- Замок проверяет код **локально**, а `auth/pin-resume` вызывается уже после
  успешной проверки; его отказ разблокировку не отменяет — он продлевает
  серверную сессию, а не решает, пускать ли человека в его же приложение.
- Замок вооружается только когда есть и сессия, и локальная копия: замок,
  который открыть нечем, и есть запирание пользователя вне приложения.
- Смена PIN пишет в Keystore **после** ответа сервера. Если запись не удалась,
  локальная копия **стирается**, а не остаётся прежней: прежний код открывал бы
  замок кодом, которого бэкенд не знает. Замок без копии просто не вооружается
  и вернётся при следующем входе или разблокировке.

Отвергнутая альтернатива — «только сервер, локального нет»: любая проверка
кода становится сетевым запросом, а отсутствие сети — неоткрываемым
приложением. Ровно тот риск, о котором предупреждает issue.

## Последствия

- Лимит попыток: в **серверном** режиме считает бэкенд (issue #51), своего
  счётчика нет. На экране блокировки код проверяется без сети, поэтому лимит
  там локальный — и персистентный (`PinAttemptStore`, DataStore), как
  предписывал ADR 0004: в памяти он обходился снятием приложения из недавних.
  Исход исчерпанных попыток — не «заблокировано навсегда», а выход в SMS-вход.
- Установка PIN остаётся на `auth/setup-pin`; `POST pin/set` и `POST pin/reset`
  не подключены — они требуют пары `otpToken` + `otpCode`, а «сброс по SMS» у
  приложения это выход и вход заново. `DELETE pin` не подключён намеренно: он
  выключил бы app-lock при живой сессии.
- `pinRequired` из `session/check` как команда не используется: замок
  защёлкивается по клиентскому правилу (фон + отсрочка), от сервера читается
  `sessionValid`. Начнёт бэкенд требовать PIN по своему таймауту — это придётся
  учесть отдельно.
- Локальный хэш по-прежнему PBKDF2 + Keystore (ADR 0004) — изменился только
  ответ на вопрос, кто задаёт код.
- Один разъезд инвариант не закрывает: **PIN, сменённый на другом
  устройстве**. Локальная копия останется прежней, замок будет её принимать, а
  `pin-resume` — отказывать. Лечить это стиранием копии по отказу можно только
  зная код ошибки, а `pin-resume` под токеном пока никто не звал (issue #194).
