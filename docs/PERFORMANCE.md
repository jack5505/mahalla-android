# Производительность: Baseline Profile и холодный старт

Эпик 13.3. Модуль `:baselineprofile` — `com.android.test`, в APK приложения не
попадает.

## Зачем

Baseline Profile — список классов и методов, нужных приложению на старте. ART
компилирует их заранее, при установке, а не интерпретирует при первом запуске.
Выигрыш заметен ровно на дешёвых устройствах, ради которых выбран minSdk 26; на
флагмане разницы почти нет, поэтому и мерить её надо не «на глаз».

Профиль лежит в `app/src/release/generated/baselineProfiles/` и коммитится:
иначе каждая сборка релиза требовала бы эмулятора. Установку профиля на
устройство делает `androidx.profileinstaller`, он уже в зависимостях `:app`.

## Ничего из этого не гоняется в CI

Обе команды ниже требуют устройства или эмулятора. Ни в CI, ни в песочнице
агента их нет (AGENTS.md), поэтому:

- профиль в репозитории **обновляет человек** — после заметных изменений
  старта (сплэш, навигация, первый экран);
- числа старта — тоже с машины человека, и сравнивать их можно только с
  числами, снятыми **на том же устройстве**.

## Снять профиль

```bash
./gradlew :app:generateBaselineProfile
```

Gradle сам скачает и поднимет эмулятор `pixel6Api34` (AOSP-образ: сервисы
Google в замере старта только шумят), прогонит
`StartupBaselineProfileGenerator` и положит результат в
`app/src/release/generated/baselineProfiles/baseline-prof.txt`. Файл — в
коммит, диффом по нему видно, что именно уехало на старте.

Профиль обходит только первые секунды: старт, прорисовка первого экрана. Дальше
поведение расходится (авторизован / не авторизован), и профиль пришлось бы
держать под каждый случай.

## Померить холодный старт

**Сначала снимите профиль** (шаг выше): замер «с профилем» требует его
наличия (`BaselineProfileMode.Require`) и без профиля честно краснеет.

```bash
./gradlew :baselineprofile:pixel6Api34BenchmarkReleaseAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.enabledRules=Macrobenchmark
```

Фильтр обязателен: без него в том же прогоне запустится
`StartupBaselineProfileGenerator`, которому нужен неминифицированный вариант
сборки (`nonMinifiedRelease`), а не `benchmarkRelease`.

Два теста на один вопрос — «профиль вообще что-то даёт?»:

- `startupWithoutBaselineProfile` (`CompilationMode.None`) — как при первой
  установке из магазина;
- `startupWithBaselineProfile` — с профилем из репозитория.

Метрика — `StartupTimingMetric`: `timeToInitialDisplay` (первый кадр) и
`timeToFullDisplay`. Смысл имеет **разница между двумя прогонами**, а не
абсолютные миллисекунды: они зависят от устройства и от того, что ещё на нём
крутится.

Результаты — в
`baselineprofile/build/outputs/connected_android_test_additional_output/`.

## Грабли

- **Эмулятор нужен API 28+.** `BaselineProfileRule` помечен
  `@RequiresApi(28)`: снять профиль на API 26–27 нечем. Отсюда `minSdk = 28` в
  модуле `:baselineprofile` — на сборку приложения (minSdk 26) это не влияет.
  Сам macrobenchmark работает и ниже, но держать в модуле два разных
  минимальных API незачем.
- **Замер на debug-сборке бессмыслен**: benchmark гоняет `benchmarkRelease` —
  тип сборки, который плагин создаёт сам поверх release.
- **Эмулятор шумит.** Пять итераций — минимум, на котором разброс холодного
  старта перестаёт перекрывать разницу между режимами компиляции. Числа с
  ноутбука под нагрузкой сравнивать с чужими нельзя.
